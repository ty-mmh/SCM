- 状態: non-normative workbench
- 役割: 未決事項、実装判断、延期、範囲外、未実証を、正典と混ぜずに管理する

- 空白の正本: [`ledger.md`](ledger.md)

## 1. 権威境界

`note/`配下の文書は、SCMの正典・参照プロファイル・適合条件を変更しない。

Noteに書かれている選択肢、仮説、実装案は、次を満たすまでSCMの決定ではない。

1. 未決事項に対して明示的な決定が置かれる。
2. 決定の出所が記録される。
3. 影響する正典文書・参照プロファイル・ケースが同期される。
4. 既存構造との衝突と剪定対象が確認される。

> **空白は、決定されるまで空白のまま保持する。実装上自然に見える補完を、正典判断へ自動昇格させない。**

## 2. 現在の使い方

日常的に参照するのは[`ledger.md`](ledger.md)だけとする。

- ユーザーは、台帳上部の`NEXT`カード一件だけを順に埋める。
- 状態遷移・API・DBの詳細は`E-*`へ置き、上流の意味を変えない範囲で実装時に決める。
- 記号・表記・証拠表示の修正は`M-*`へ置く。
- 来歴監査は`G-*`へ置く。
- 延期・範囲外は`D-*`、未実証は`V-*`へ置く。

U-01は、[SCM系成立とBootstrap](../docs/09-system-establishment-and-bootstrap.md)へ同期され、`resolved`となった。現在はU-02を扱う。

旧Noteの詳細と、2026-08-04時点の全量スナップショットの対応は[`archive/`](archive/README.md)で追跡する。

## 3. 台帳の状態

| 状態 | 意味 |
|---|---|
| `open` | 決定が必要で、まだ回答がない |
| `provisional` | 仮決めがあるが、実装・検算で変更しうる |
| `deferred` | SCMの射程にあるが、現在のプロファイルでは扱わない |
| `out_of_scope` | 現行SCMの責務として扱わない |
| `unvalidated` | 概念または仕様は置かれたが、実装・ケース・外部レビューで未確認 |
| `resolved` | 明示的決定が正典へ同期済み |

## 4. 判断主体

| authority | 意味 |
|---|---|
| `user` | 存在論、帰属、意味境界をユーザーが言葉で決める |
| `engineering` | 上流の意味を変えず状態遷移・API・DBへ落とす |
| `mechanical` | 記号衝突、リンク、表記、証拠表示を同期する |
| `joint-review` | 由来監査や外部レビューを伴い、単独で確定しない |

## 5. 更新規則

- 新しい空白を発見した場合、正典へ直接補完せず、まず`ledger.md`へ一意IDで追加する。
- 同じ空白を複数ファイルへ本文ごと複製しない。
- 会話内で回答が置かれた場合、その回答とアシスタント・外部レビュアーの提案を区別する。
- 一項目の決定が別の空白を生んだ場合、別IDとして追加する。
- engineering項目の途中で存在論的判断が必要になった場合、`U-*`カードへ昇格する。
- `deferred`は不要を意味しない。
- `unvalidated`は誤りを意味しない。
- Noteを理由にv0.1 Coreケースを増やさない。必要なら既存ケースのvariant、置換、統合を検討する。
