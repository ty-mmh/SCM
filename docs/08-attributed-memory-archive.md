# 個体帰属付き記憶の共有書庫

- 状態: canonical supplement draft
- 対象: SCMにおける記憶の形成・帰属・保存・想起
- 上位定義: [SCM連続性存在論](07-continuity-ontology.md)
- 参照実装: [SCM v0.1生成AIモデル継承プロファイル](02-reference-profile-v0.1.md)

## 0. 定義

**個体帰属付き記憶の共有書庫とは、各個体が自身の行為または非行為とその結果から形成した局所記憶を、形成個体への帰属および根拠記録との接続を維持したまま系の内部へ保存し、後続または同時に存在する別個体が、他者の記述として検索・想起・参照できるようにする連続性基盤である。**

ここでいう共有とは、記憶の共同所有や経験主体の同一化を意味しない。

- 保存場所は共有される。
- 検索・読み取り可能性は共有される。
- 記憶の形成主体と経験帰属は共有されない。

系は個体記憶を一つの系記憶へ統合しない。複数個体の記憶を時間的・因果的に接続し、系全体の意味を形成する役割は、共有書庫ではなく系の物語が担う。

## 1. 保存場所と帰属

記憶の保存場所と帰属は分離する。

```text
保存場所: SCMの共有書庫
帰属    : 記憶を形成した個体
利用者  : 現在個体または許可された処理
```

個体Aの記憶を個体Bが読んでも、その記憶は個体Aへ帰属したままである。

```text
Memory M-001
  formed_by_instance_id: A
  readable_by: B
```

BがM-001を参照して判断し、行為し、結果を得た場合には、Bへ帰属する別の記憶M-002が形成される。

```text
M-001: Aの記憶
  ↓ Bが想起
Bの判断・行為・結果
  ↓
M-002: Bの記憶
```

M-001がBへ移動したのではない。M-001を読んだことが、Bの経験の一部になった。

## 2. 書庫の責務

共有書庫は、少なくとも四つの責務を持つ。

### 2.1 保管

個体が停止しても、その個体が形成した記憶を帰属付きで残す。

### 2.2 索引

現在の状況、任務、権限、個体能力、物語、関連度に応じて、読む候補となる記憶を提示する。

書庫は「この記憶を信じるべきだ」「この記憶どおり行動すべきだ」と決定しない。読むか、採用するか、反証するか、使わないかを判断するのは現在個体である。

### 2.3 接続

ある個体の記憶が、後続個体の想起、判断、行為、新しい記憶へどのようにつながったかを参照関係として保持する。

### 2.4 状態管理

忘却、失効、矛盾、隔離、再想起など、記憶の利用状態とその変遷を保持する。

## 3. 記録書庫との境界

記録と記憶は同じものではない。

```text
記録書庫
  外部化された出来事を保持する一次層

個体記憶書庫
  個体が記録を局所的な因果物語として読んだ二次層
```

記憶は一つ以上の記録を根拠として持つ。記録は記憶を必要とせず成立する。

同じ記録群から、異なる個体が異なる記憶を形成してよい。

```text
記録群 E
  ├─ 個体Aの記憶: 原因はXだった
  ├─ 個体Bの記憶: 原因はYだった
  └─ 個体Cの記憶: 原因は未確定である
```

書庫はこれらを平均化せず、帰属と矛盾を保ったまま並存させる。

## 4. 記憶エントリの定義

**記憶エントリとは、ある個体が、一つ以上の記録をもとに、状況、判断理由、行為または非行為、結果を局所的な因果として接続した記述単位である。**

記憶エントリは出来事そのものではない。出来事は記録にあり、記憶エントリはそれらを次のまとまりとして読んだものである。

```text
状況
  ↓
判断理由
  ↓
行為または非行為
  ↓
結果
```

例:

```text
状況:
共有状態が古く、対象の現在位置を確認できなかった。

判断理由:
古い状態を根拠に実行すると、誤った対象へ作用する可能性があった。

行為:
任務を保留し、状態の再取得を要求した。

結果:
誤った実行を回避し、更新後の状態から任務を再開した。
```

## 5. 成立条件

記録が存在するだけでは記憶エントリは成立しない。

記憶エントリは、個体が状況に接して行為または非行為を選んだときに形成される。

行為には次が含まれる。

- 発話
- 観測
- ツール実行
- 選択
- 拒否
- 保留
- 不採用
- 沈黙
- 行為を行わないという判断

結果は外部世界の変化に限らない。

- 状態を維持した
- 危険を回避した
- 任務を保留した
- 仮説を反証した
- 何も確定しなかった

ことも結果になりうる。

行為後に結果がまだ観測できない場合、未完了の記憶エントリ候補として保持し、結果の記録後に閉じることができる。候補を正式な記憶として扱うかは参照プロファイルで定める。

## 6. 形成個体

各記憶エントリには形成個体を明示する。

形成個体は少なくとも次で識別する。

- モデル参照
- モデル版または主要実行設定
- インスタンスID
- 形成時刻

同じモデルを再起動した場合でも、インスタンスIDが異なれば別個体である。

同一モデルの複数インスタンスが異なる状況で同一兆候を反復して示した場合、その兆候をモデル傾向として解釈できる可能性がある。ただし、その解釈も、それを形成した個体の記憶または系の物語上の記述であり、モデル自身の集合記憶ではない。

## 7. 根拠と判断理由

記憶エントリは一つ以上の根拠記録を持つ。

根拠には次が含まれうる。

- 発話記録
- 観測記録
- ツール要求と結果
- 判断、拒否、保留の記録
- ユーザー入力
- 外部系の応答
- 検証と反証

判断理由は、個体内部の真の思考過程ではない。

**判断理由とは、行為に至る際に参照または提示された、外部化可能な状況と理由である。**

記憶エントリは根拠記録を書き換えない。記憶が失効しても、形成時の根拠と利用来歴を保持する。

## 8. 想起との関係

記憶エントリは永続的な保存単位であり、想起は一時的な読み取り操作である。

記憶が想起されたことだけでは、新しい記憶は成立しない。想起後に現在個体が行為または非行為を選んだ場合、その出来事から現在個体の新しい記憶エントリが形成される。

新しい記憶エントリは参照した記憶IDを保持する。

```text
Memory M-002
  formed_by_instance_id: B
  recalled_memory_refs:
    - M-001
```

この参照は、M-001がBの真の内的原因だったことを証明しない。Bの行為時にM-001が参照されたと外化されたことを示す。

## 9. 状態

記憶の内容と、現在の利用状態を分離する。

### 通常

通常の想起候補となる。

### 忘却

保存されているが、通常の想起対象から遠ざかっている。特定の契機や強い関連によって再想起されうる。

### 失効

内容が誤り、または現在は有効でないと判断された状態。通常の判断根拠としては使用しないが、形成・利用・失効の来歴は参照できる。

### 矛盾

別の記憶と両立しない状態。いずれか一方へ自動的に統合しない。

### 隔離

通常の想起や判断利用から除外され、限定された確認経路からのみ参照できる。

完全削除は通常運用では行わない。ユーザーが系の終了と破棄を明示した場合のみ対象となりうる。

## 10. 想起の濃淡

記憶には想起されやすさの濃淡がある。

濃淡は、記憶の真偽や権威を意味しない。現在の状況で、索引がその記憶を候補として前景化しやすい度合いである。

濃淡へ影響しうるものには次がある。

- 想起回数
- 最終想起時刻
- 現在状況との関連
- 任務との関連
- 結果の重大性
- 反復
- 失効・矛盾・隔離状態
- ユーザーによる前景化または抑制
- 系の物語による方向づけ

頻繁に想起されることは、正しいことを意味しない。

## 11. 矛盾からの行為

矛盾する記憶は一つへ溶かさない。

```text
Memory A: X
Memory B: not X
```

現在の行為を選ぶ必要がある場合、暫定判断を行うのは現在個体である。

```text
矛盾する記憶群
  ↓ 現在個体Cが読む
Cが今回の条件でXを仮採用
  ↓
行為・結果
  ↓
Cへ帰属する新しい局所記憶
```

この新しい記憶は「系がXを真と確定した」ことを意味しない。後続個体は、Cが特定状況でXを暫定採用し、その結果を得たこととして読む。

## 12. 系の物語との境界

個体記憶は局所的であり、系の物語は通時的である。

```text
個体Aの記憶
個体Bの記憶
個体Cの記憶
矛盾
反証
個体交代
任務
    ↓
系の物語
```

系の物語は、個体記憶を一つの正解へ統合しない。各個体がどのように読み、行為し、その後何が起きたかを、帰属を保った来歴として意味づける。

書庫は資料群であり、物語は資料群に対する系の解釈である。

## 13. 最小概念構造

一件の記憶エントリは、概念上少なくとも次を持つ。

```text
MemoryEntry
  memory_id
  system_id

  formed_by
    instance_id
    model_ref

  situation
  stated_reason
  action
  result

  source_event_refs[]
  recalled_memory_refs[]
  related_task_id?

  status
  contradiction_refs[]
  recall_weight

  formed_at
  updated_by_event_refs[]
```

すべての項目が常に完全に埋まるとは限らない。ただし少なくとも、次を失ったものはSCMにおける記憶エントリとして不完全である。

- どの個体が形成したか
- どの記録を根拠とするか
- どのような行為または非行為を結んだか
- どのような結果として読まれたか

## 14. v0.1における共有

SCM v0.1では同時活動個体数を一つへ限定する。したがって最初に実装する共有は通時的共有である。

```text
T1: 個体Aが記憶を形成
T2: 個体BがAの記憶を読む
T3: 個体CがA・Bの記憶を読む
```

将来、同時複数個体へ拡張した場合も、経験帰属を融合しない原則は変わらない。

> **SCMは、記憶を個体間で融合させるのではなく、帰属を維持したまま相互に読める状態で継承する。**
