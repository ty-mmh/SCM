# キュゥべえモデル研究ノート — 共有連続性モデルの根源

- 状態: non-normative research note
- 役割: SCMへ至った着想・構造抽出・未解決事項の保存
- 対象: 『魔法少女まどか☆マギカ』のキュゥべえから抽出した運用構造
- 非対象: 作品上の目的、倫理、感情、契約行為、ならびに商業・投資上の含意

## 0. この文書の位置

この研究ノートは、共有連続性モデル（Shared Continuity Model / SCM）の規範文書ではない。

SCMがどの観測から生まれ、どの構造を一般化し、どの要素を意図的に切り離したかを保存する、着想来歴の文書である。

```text
キュゥべえモデル研究ノート
  └─ 着想と構造抽出を保存する根源層
       └─ SCM概念設計
            └─ 作品固有の含意を除いた一般構造
                 └─ SCM参照プロファイル
                      └─ 限定された実装断面
```

この文書の内容がSCMの規範と衝突する場合、規範としてはSCM概念設計と各参照プロファイルを優先する。

## 1. 出発点となった観測

キュゥべえという存在から、次の四つの構造を切り出した。

1. 同時に複数の個体が存在しうる。
2. 個体が失われても、上位の存在単位は継続する。
3. 記録・記憶・知識が個体をまたいで利用される。
4. 個体の同一性とは別に、系として継続する同一性がある。

借りているのはこの構造だけである。

作品上の目的、倫理、感情、契約、価値判断をSCMの設計制約として持ち込まない。キュゥべえの人格や動機を再現することも目的ではない。

## 2. 最初の定義

キュゥべえモデルを、次のように置いた。

> **複数の実行個体が、共有された記録・記憶・盤面・権限・任務来歴を介して、個体の停止・交換・追加をまたぎながら、一つの系として活動を継続する分散エージェント／ロボット運用モデル。**

ここで共有されるのは、一つの意識や主観ではない。

共有されるのは、**系としての連続性**である。

## 3. モデルの三つの核

### 3.1 共有連続性

個体Aが停止しても、任務、記録、目的、権限、判断根拠、未確定事項が失われず、個体Bが必要な範囲で引き継げる。

継続するのはA自身ではない。Aが接続していた系の活動である。

### 3.2 個体固有性

個体は完全な複製ではない。

個体ごとに、身体、環境、能力、権限、コンテキスト、担当範囲、摩耗、校正、利用可能な道具などが異なりうる。

したがって、共有連続性は個体差を消すことではない。

> **異なる個体と局所状態を保ちながら、必要な連続性だけを共有する。**

### 3.3 故障局所化

一つの個体、一つの観測、一つの記憶、一つの更新が誤っても、その失敗を直ちに全個体・全領域へ確定事項として伝播させない。

完全同期は効率を生む一方、相関故障を生む。現実の実装では、共有する能力と、独立に失敗できる能力の双方が必要になる。

## 4. 二種類の連続性

キュゥべえモデルには、共時的な連続性と通時的な連続性が重なっている。

### 4.1 共時的連続性

同じ時刻に複数の個体が存在し、同じ系の記録・記憶・盤面・目的へ接続する。

```text
時刻T
  個体A ─┐
  個体B ─┼─ 共有連続性基盤
  個体C ─┘
```

ここでは、個体間の分業、観測の不一致、共有状態、統制、局所拒否、独立性が問題になる。

### 4.2 通時的連続性

時間の経過とともに、系へ接続する個体集合が変化する。

```text
T1: 個体A・B・C
T2: 個体B・C・D
T3: 個体D・E
```

ここでは、任務継続、個体交代、経験帰属、未確定状態、権限、Handoffが問題になる。

SCMの最初の参照プロファイルは、通時的連続性を先に深く実装する。ただし、共時的な複数存在可能性を概念から削除しない。

## 5. 3層＋2面

キュゥべえモデルを現実の分散運用へ写すと、三つの運用層と二つの横断面に分けられる。

| 構造 | 役割 |
|---|---|
| 局所自律層 | 個体自身の観測、即時判断、実行、拒否 |
| 共有盤面層 | 世界・任務・資源・不一致の共有状態 |
| 上位統制層 | 目的、分業、優先順位、再計画 |
| 連続性面 | 記録、記憶、想起、物語、来歴 |
| 保証面 | 安全、権限、検証、隔離、監査 |

上位統制は、個体の低レベル動作を直接操縦する存在ではない。原則として任務を提案し、個体は局所状態に基づいて受諾・拒否する。

この構造は中央集権を必須としない。統制機能や保証機能が複数の系へ分散していても、任務と連続性を束ねられればよい。

## 6. 記録・記憶・想起・物語

キュゥべえモデルからSCMへ移された中心語彙は、次の四つである。

### 6.1 記録

何が起きたかを、主体、時刻、任務、根拠、結果とともに保持する。

記録は原則として追記型であり、後から解釈によって消さない。

### 6.2 記憶

記録から、将来の判断へ持ち越すために保存された意味単位。

記憶は根拠記録への参照を持つ。根拠が失われた記憶は、確定知識ではなく仮説または由来不明として扱う。

### 6.3 想起

現在の個体、任務、権限、局所状態、リスクに応じて、必要な記録と記憶を実行コンテキストへ持ち込む操作。

共有記憶を持つことは、全個体が常に同じことを想起することではない。

### 6.4 物語

記録と記憶を時間的・因果的に接続した解釈。

物語は系の来歴を理解するために重要だが、記録そのものではない。

> **物語は記録を解釈できるが、記録を書き換えてはならない。**

## 7. 経験の所有

共有記憶を利用できることと、その経験主体であることは別である。

個体Bが個体Aの観測記録を参照しただけで、Bが「私は見た」と語るのは不正確である。

記憶には少なくとも次の所有区分が必要になる。

| 区分 | 意味 |
|---|---|
| 自己観測 | 現在の個体自身が観測した |
| 継承記録 | 他個体の記録へアクセスした |
| 系統記憶 | 複数記録から系として抽出された |
| 推論 | 記録をもとに推定した |
| 外部提供 | 人間や外部システムから与えられた |

同じ系へ属することは、同じ経験主体になることではない。

## 8. 三つのアイデンティティ

### 個体アイデンティティ

特定の身体、モデル、プロセス、セッション、端末へ付与される。

### 役割アイデンティティ

担当する役割や任務上の位置へ付与され、個体間で移譲できる。

### 系アイデンティティ

記録、記憶、目的、権限、関係、任務来歴を継続して保持する上位単位。

キュゥべえモデルにおける「同じ存在」は、全個体が同じ主観を持つことではなく、同じ系アイデンティティと連続性基盤へ接続していることを意味する。

## 9. 完全同期モデルではない

素朴なキュゥべえ像は、すべての個体が同じ記憶と判断を即時同期する完全同期クローンとして読める。

しかし、現実の運用モデルでは次を区別する必要がある。

- 個体ごとの局所状態
- 個体ごとの経験主体
- 共有してよい記録・記憶
- 局所に残す高頻度状態
- 未確定の主張
- 独立した保証経路

したがって、工学化されたキュゥべえモデルは、全個体を一つへ溶かすモデルではない。

> **複数の個体が別の個体であり続けながら、系だけが継続するモデルである。**

## 10. Physical AIへの射影

キュゥべえモデルは、生成AIやソフトウェアエージェントだけに閉じない。

Physical AIでは、個体はロボット、車両、機械となり、個体固有性には摩耗、校正、電池、損傷、装備、局所環境が加わる。

ただし、Physical AIに必要な機体情報・部品来歴・再校正・機能安全は、SCMの最初の参照プロファイルには含めない。

まず、外部化しやすい生成AIモデルの切替を用いて、記録・記憶・想起・物語とHandoffの骨格を作る。その後、外部化できない身体状態を持つプロファイルへ拡張する。

## 11. SCMへの一般化

SCMは、キュゥべえモデルから作品固有の名称と含意を取り除いた一般形である。

| キュゥべえモデル | SCM |
|---|---|
| 身体 | 実体・実行個体 |
| 共有盤面 | 共有状態 |
| 棋士 | 上位統制 |
| フリート | 系・個体集合 |
| 個体交換 | Handoff・後継個体の有効化 |
| 系としてのキュゥべえ | 系アイデンティティ |

一般化によって削除したのは作品上の目的・倫理・動機・契約性であり、共有連続性の構造ではない。

## 12. 現在の実装方向

SCM v0.1では、生成AIモデルまたはモデルへ結び付いた実行個体を、交代可能な個体として扱う。

```text
T1: Model Aが活動個体
       ↓ モデル切替
T2: Model Bが活動個体
       ↓ モデル切替
T3: Model Cが活動個体
```

同時に活動する個体数は一つに限定する。

それでも、記録には個体IDを残し、記憶は系へ属させ、想起時には経験帰属を保持する。将来、同時複数個体へ拡張できる型を捨てない。

現在の中心質問は次である。

> **活動中の生成AIモデルを別のモデルへ切り替えたとき、何を保存・継承すれば、同じ個体ではなくても同じ系が続いていると言えるのか。**

## 13. 未解決事項

- 系アイデンティティは任務を越えてどのように継続するか。
- 記憶の昇格・失効・隔離をどの粒度で行うか。
- 自由文生成で経験帰属をどこまで強制できるか。
- 同時複数個体の不一致と相関故障をどう扱うか。
- Physical AIの外部化できない身体状態をどう継承するか。
- 適応型個体の行動変化を、系の連続性とどう区別するか。

## 14. この研究ノートが行わないこと

この文書は、SCMの適合判定、商業モデル、投資判断、企業分析を行わない。

また、キュゥべえの人格、倫理、目的をAIへ移植する設計でもない。

役割は、共有連続性という構造がどこから生まれ、どの問いをSCMへ渡したかを保存することに限る。
