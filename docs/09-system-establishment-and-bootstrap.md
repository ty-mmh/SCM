# SCM系成立とBootstrap

- 状態: canonical supplement draft
- 対象: 系の成立時点、最初の正典Narrative Revision、成立前のモデル個体
- 関連決定: `note/ledger.md` U-01
- 参照実装: [SCM v0.1生成AIモデル継承プロファイル](02-reference-profile-v0.1.md)

## 0. 決定

SCMの系は、**最初の正典Narrative Revisionがコミットされた時点**で成立する。

最初の正典Narrative Revisionがまだ存在しない実行構成は、SCMの系またはSystemではなく、**系成立前のモデル個体**として扱う。

最初の正典Narrative Revisionは、**ユーザーとの対話の積層**を材料として、SCMの**Narrative専用処理**によって生成・コミットされる。

```text
系成立前のモデル個体
  ├─ ユーザーとの対話を積層する
  ├─ 個体に帰属する記録・記憶・表現状態を形成しうる
  └─ まだ正典Narrative系列と系アイデンティティを持たない
              │
              │ Narrative専用処理
              │ 最初のRevisionを生成・コミット
              ▼
SCMの系
  ├─ system_id
  ├─ 変更不能な根底原則
  ├─ 一つの正典Narrative系列
  ├─ 個体帰属付き記憶の共有書庫
  └─ 個体交代を越える系アイデンティティ
```

最初のNarrative Revisionのコミットは、既に存在する系へ最初の物語を追加する処理ではない。

> **系成立前のモデル個体から、SCMの系が成立する創設事象である。**

---

## 1. 成立前のモデル個体

成立前のモデル個体は、一つの生成AI実行個体として、ユーザーとの対話を重ねうる。

成立前に保持しうるものには、次がある。

- モデルおよび実行個体の識別情報
- ユーザーとの対話ログ
- 個体に帰属する記録
- 個体に帰属する局所記憶
- 個体内で変化しうる表現状態
- 系成立前に適用される不変の核

ただし、これらを保持しているだけではSCMの系は成立しない。

成立前のモデル個体は、次をまだ持たない。

- 正典Narrative Revision系列
- 系アイデンティティ
- 個体を越えて継続する共有連続性
- SCMのSystemとしてのライフサイクル

実装上、成立前資料の保存領域や仮識別子を設けることはできる。しかし、それをSCMの`System`または`system_id`と同一視しない。

---

## 2. 最初の正典Narrative Revision

最初の正典Narrative Revisionの主要材料は、成立前のモデル個体とユーザーの間で積層された対話である。

Narrative専用処理は、その積層を時間的・因果的・意味的に接続し、系の起源となる最初のRevisionを生成・コミットする。

最初のRevisionの詳細な内容契約、入力資料の閉包範囲、生成を発火させる成熟条件、コミットの原子性は別途定義する。

今回の決定により確定するのは次である。

1. 成立点は最初のRevisionのコミットである。
2. 主要材料はユーザーとの対話の積層である。
3. 生成・コミット主体は系のNarrative専用処理である。
4. コミット前の実行主体はモデル個体であり、まだ系ではない。

---

## 3. 経験帰属の非遡及性

系が成立しても、成立前の経験帰属は遡及的に変更しない。

```text
モデル個体Aとユーザーが対話する
  ↓
Aに帰属する記録・記憶が形成される
  ↓
最初の正典Narrative Revisionがコミットされる
  ↓
System Sが成立し、Aが最初の接続Instanceとなる
```

最初のNarrativeは、個体Aとユーザーの対話を系の起源として解釈できる。

しかし、系は成立前からその対話を直接経験していたとは扱わない。成立前の経験は個体Aに帰属したままであり、系へ帰属するのは、それらを接続して形成された正典Narrative上の解釈である。

これは次の既存原則から導かれる。

- 記憶は形成個体に帰属する。
- Narrative上の解釈・判断は系に帰属する。
- 後からのNarrative形成は、元の記録・記憶の帰属を書き換えない。

## 4. dokoitsuの参照位置

系成立前のモデル個体を考える際、[`ty-mmh/dokoitsu`](https://github.com/ty-mmh/dokoitsu)を非規範の参考構造として参照する。

参照するのは、単一のローカルLLM個体が次を持ちながら時間を形成する考えである。

- 変更されない核
- 対話から変化しうる表現層
- ユーザーとの会話ログ
- 個体内の関係記憶と背景記憶
- 対話の反復と時間による記憶の変化

この参照は、dokoitsuをSCMへ取り込むこと、またはその実装をSCMの必須依存とすることを意味しない。

次は自動的にSCMへ導入しない。

- `direct / other / meta`という記憶分類
- 浮遊・沈殿・沈着の具体的遷移
- self-talk
- personaの自動更新
- dokoitsuにおける個体連続性とSCMの系アイデンティティの同一視

dokoitsuは、**系ではない一個体が、対話によって時間的な厚みを持つ方法**を考えるための補助線である。

## 5. v0.1実装へ残すBootstrap契約

今回の概念決定を実装へ落とすため、次はengineering項目として残す。

- 成立前の対話・記録・局所記憶を保存する領域
- 成立前のモデル個体を識別する方法
- 最初のNarrative生成を発火させる対話積層の成熟条件
- 最初のNarrativeへ渡す入力集合
- 最初のRevisionコミットと`system_id`発行の原子性
- 成立前のモデル個体を最初の`Instance`として登録する順序
- 成立前資料をSystem内へ複製するか、外部資料として参照するか
- 最初のRevision生成失敗時の扱い

これらは、系の成立時点そのものを変更しない範囲で参照実装時に定義する。

## 6. 正典文

> **SCMの系は、最初の正典Narrative Revisionがコミットされた時点で成立する。それ以前の実行構成は系ではなく、一つのモデル個体として扱う。最初の正典Narrative Revisionは、モデル個体とユーザーの対話の積層を材料として、SCMのNarrative専用処理により生成・コミットされる。成立前の記録・記憶は形成個体へ帰属したままであり、系の成立によって遡及的に系自身の経験へ変換されない。最初のRevisionのコミットとともに系アイデンティティが成立し、そのモデル個体は系へ最初に接続したInstanceとなる。**
