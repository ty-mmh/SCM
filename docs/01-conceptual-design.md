# 共有連続性モデル（SCM）概念設計 v0.1

- 状態: canonical draft
- 対象: 実装基体に依存しない構造核
- 注意: v0.1参照実装の適合範囲は [02-reference-profile-v0.1.md](02-reference-profile-v0.1.md) で限定する

## 0. 定義

共有連続性モデルとは、複数の実行個体が、記録・記憶・共有状態・目的・権限・任務来歴からなる**共有連続性基盤**へ接続し、各個体の局所自律と実体固有性を保ちながら、個体の停止・交換・追加をまたいで一つの系として活動を継続する分散運用モデルである。

共有されるのは意識でも瞬間的判断でもない。共有されるのは、**系としての連続性**である。

構造上の前提は四つである。

1. 同時に複数の実行個体が存在しうる。
2. 個体が失われても系は継続する。
3. 記録と記憶が個体をまたいで利用される。
4. 個体より上位に、継続する存在単位がある。

## 1. モデルの核

### 共有連続性

個体Aが停止しても、作業・記録・目的・権限・判断根拠が失われず、後継個体Bが必要な範囲で引き継げる。

### 実体固有性

個体は完全な複製ではない。実体、環境、権限、コンテキスト、担当範囲などの固有状態を持つ。

### 故障局所化

一つの個体または一つの更新が誤っても、その失敗が直ちに全個体へ伝播しない構造を目指す。

したがってSCMは、全個体が同じものを知り、同じように動くモデルではない。

> 異なる実体と局所状態を持つ個体群が、必要な連続性だけを共有するモデルである。

## 2. 基本構造 — 3層＋2面

| 構造 | 主な役割 | 主な時間幅 |
|---|---|---:|
| 局所自律層 | 即時判断、実体制御、局所作業、拒否 | ミリ秒〜秒 |
| 共有状態層 | 現在状態の集約、共有、競合・不一致の保持 | 秒〜分 |
| 上位統制層 | 目的、分業、優先順位、再計画 | 分〜日 |
| 連続性面 | 記録、記憶、想起、物語、任務来歴 | 全期間 |
| 保証面 | 安全、権限、検証、隔離、監査 | 全時間幅 |

```text
        人間・組織・外部目的
                 │
                 ▼
            上位統制層
   目標分解・配分・優先順位・再計画
                 │
              任務提案
                 ▼
            共有状態層
  世界状態・作業状態・資源・不一致・信頼度
      ▲          ▲          ▲
      │          │          │
   個体A       個体B       個体C
   局所自律     局所自律     局所自律
   実体状態     実体状態     実体状態
   拒否権       拒否権       拒否権

────────────────────────────
連続性面：記録・記憶・想起・物語・任務来歴
保証面　：安全・認証・検証・隔離・ロールバック
────────────────────────────
```

上位統制から個体へ渡されるものは、原則として低レベルの動作命令ではなく**任務提案**である。個体は、自身の状態と制約に基づいて、受諾・条件付き受諾・保留・拒否・上位への引き上げを行える。

## 3. 局所自律

各個体は少なくとも次を保持する。

- 自身の観測
- 自身の実体・実行環境の状態
- 現在の任務
- 自身の能力と制約
- 即時の安全判断
- 通信断時の行動
- 上位提案を拒否する能力

局所拒否権のない構成はSCMの要件を満たさず、中央遠隔制御型の構成に近い。

拒否権は、個体の自己申告を無条件に真実とみなすことを意味しない。拒否は安全側へ倒す制御として即時有効にできる一方、拒否理由は記録され、必要に応じて別経路で検証される。

## 4. 共有状態

共有状態は「真実の世界」ではない。複数の個体が提出した観測・推定・作業状態・資源状態を統合した、運用上の共有信念状態である。

共有される単位は、確定事実よりも主張に近い。

```text
共有主張 =
  内容
  観測・申告主体
  観測・申告時刻
  根拠
  信頼度
  有効範囲
  有効期限
  反証・不一致
```

単一個体の申告と、独立した観測・検証は区別される。不一致は即座に一方へ潰さず、未確定状態として後継個体へ継承できなければならない。

## 5. 上位統制

上位統制層は、次を扱う。

- 全体目的と完了条件
- タスク分解
- 個体への役割・任務提案
- 資源と時間の配分
- 優先順位変更
- 競合解消
- 障害時の再計画
- 個体停止時の引き継ぎ開始
- 人間や外部組織との接続

SCMは中央集権を必須としない。統制機能は複数のシステムへ分担できる。必要なのは、個体をまたいで任務と連続性を束ねられることである。

## 6. 連続性面

### 記録

何が起きたか、誰が観測・申告・実行したか、どの任務に属するか、何を根拠にしたかを追記型で保持する。訂正が必要な場合も元記録を消さず、後続の記録・状態遷移として残す。

### 記憶

記録から、将来の判断へ持ち越す意味単位として保存されたもの。記憶は根拠記録への参照を持つ。根拠を失った記憶は確定知識ではなく、仮説または由来不明として扱う。

### 想起

現在の個体・任務・権限・リスクに応じて、必要な記録と記憶を現在の実行コンテキストへ持ち込む操作。同じ記憶基盤へ接続していても、全個体が常に同じものを想起するわけではない。

### 物語

記録と記憶を時間的・因果的に接続した解釈。複数の物語が併存してよい。ただし、物語は記録を解釈できるが、記録を書き換えてはならない。

## 7. 経験の所有

共有記憶を利用できることと、その経験主体であることは別である。

| 区分 | 意味 |
|---|---|
| 自己観測 | 現在の個体自身が観測した |
| 継承記録 | 他個体の記録へアクセスした |
| 系統記憶 | 複数記録から系として抽出された |
| 推論 | 記録をもとに推定した |
| 外部提供 | 人間や外部システムから与えられた |

個体Bが個体Aの観測記録を参照しただけで、「私は観測した」と表現してはならない。

## 8. 三種類のアイデンティティ

### 個体アイデンティティ

特定のプロセス、セッション、端末、実体へ付与される。個体Aの経験は、Bが参照できてもBの経験にはならない。

### 役割アイデンティティ

担当役割や任務上の位置に付与され、個体間で移譲できる。

### 系アイデンティティ

記録、記憶、目的、権限、関係、任務来歴を継続して保持する上位単位。接続個体集合が変わっても継続する。

```text
時刻T1：個体A・B・C
時刻T2：個体B・C・D
時刻T3：個体D・E

個体集合は変化しているが、
系アイデンティティと任務来歴は継続する。
```

## 9. 保証面

保証面の原則は次である。

> 共有された知能は便利だが、正しいとは限らない。

保証面は、権限確認、安全停止、異常個体の隔離、操作ログ、監査、人間介入、独立検証などを含みうる。v0.1参照実装では、一般的な保証基盤を完成させず、Handoffに必要な限定範囲だけを扱う。

## 10. Handoff — SCMの中心操作

SCMの中心質問は次である。

> 個体Aが消え、個体Bが活動を継続するとき、何を系として保持し、何をBへ継承し、何を継承してはならないか。

継承する対象には、任務、進捗、成果物、根拠記録、共有記憶、未確定事項、現在有効な権限・制約が含まれる。

継承してはならないものには、個体Aそのもののアイデンティティ、Aの経験をB自身の経験とする一人称、根拠のない確定性、古い状態の無条件な有効性、Aにのみ与えられた権限が含まれる。

Handoffは、出発個体が自身を複製する操作ではない。系がLedgerと現在状態から、後継個体に必要な連続性を再構成する操作である。

## 11. 設計不変条件

1. 個体の停止によって任務来歴が失われない。
2. 共有された情報には必ず出所がある。
3. 他個体の経験を自己経験として偽装しない。
4. 上位統制は局所安全判断を迂回できない。
5. 個体は不適切な任務を拒否できる。
6. 物語は記録を上書きできない。
7. 更新は段階展開され、巻き戻せる。
8. 一つの故障を個体・領域・系単位で隔離できる。

I7・I8は構造核に残すが、v0.1参照実装では適合を主張しない。I7の復元範囲とI8の一般的故障局所化は、将来版で規範文を精密化する。

## 12. SCMではないもの

- 局所自律と拒否権を持たない単なる中央制御
- 任務・記憶・来歴の継続を持たない単なるマルチエージェント
- 同じDBを読むだけの共有データベース
- 故障局所化を欠く完全同期クローン
- 意識や主観的自己の移送を主張する人格アップロード

## 13. プロジェクトの第一目的

SCMの第一目的は、共有連続性を持つ記憶系を構造的に設計・実装することである。診断仕様、違反行列、ケースは、実装と並行して整備し、観測結果を構造へ還流させるための補助成果物である。

> **構造なき診断を先行させない。診断なき構造を固定しない。**
