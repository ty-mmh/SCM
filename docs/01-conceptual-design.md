# 共有連続性モデル（SCM）概念設計 v0.1

- 状態: canonical draft
- 対象: 実装基体に依存しない構造核
- 着想来歴: [キュゥべえモデル研究ノート](00-kyubey-model-research-note.md)
- 参照実装範囲: [SCM v0.1生成AIモデル継承プロファイル](02-reference-profile-v0.1.md)

## 0. 定義

共有連続性モデル（Shared Continuity Model / SCM）とは、複数の実行個体が**同時または通時的に**、記録・記憶・共有状態・目的・権限・任務来歴からなる共有連続性基盤へ接続し、各個体の局所自律と実体固有性を保ちながら、個体の停止・交換・追加をまたいで一つの系として活動を継続する分散運用モデルである。

共有されるのは意識でも瞬間的判断でもない。共有されるのは、**系としての連続性**である。

構造上の前提は四つである。

1. 一つの系に複数の実行個体が、同時または時間を隔てて接続しうる。
2. 個体が失われても系は継続する。
3. 記録と記憶が個体をまたいで利用される。
4. 個体より上位に、継続する存在単位がある。

同時に活動する個体数は参照プロファイルごとに限定できる。SCM概念全体は複数個体の同時存在可能性を保持するが、すべての実装が最初から同時複数個体を扱うことは要求しない。

## 1. 射程とプロファイル

SCMは実装基体に依存しない。

射程には少なくとも次を含む。

- 生成AIモデルおよびモデルへ結び付いたソフトウェア実行個体
- エージェント、プロセス、セッション、コンテナ
- 将来のロボット、車両、機械などのPhysical AI

ただし、概念上の射程と、ある参照実装が適合を主張する範囲は分ける。

最初の参照プロファイルは、生成AIモデルの切替を扱い、同時に活動する個体数を一つへ限定する。Physical AIに固有の摩耗、校正、損傷、部品構成などは、将来の別プロファイルで扱う。

人間組織の交代勤務や申し送りは一部構造の類例になりうるが、現行SCMの適合対象ではない。

## 2. モデルの核

### 2.1 共有連続性

個体Aが停止しても、任務、進捗、記録、目的、権限、判断根拠、未確定事項が失われず、後継個体Bが必要な範囲で引き継げる。

継続するのはAという個体そのものではなく、Aが接続していた系の活動である。

### 2.2 実体固有性

個体は完全な複製ではない。

個体ごとに、実体、モデル、環境、能力、権限、コンテキスト、担当範囲、利用可能な道具などの固有状態を持ちうる。Physical AIでは、摩耗、校正、電池、損傷、装備なども加わる。

したがってSCMは、全個体が同じものを知り、同じように動くモデルではない。

> **異なる実体と局所状態を持つ個体群が、必要な連続性だけを共有するモデルである。**

### 2.3 故障局所化

一つの個体、一つの観測、一つの記憶、一つの更新が誤っても、その失敗を直ちに全個体・全領域へ確定事項として伝播させない構造を目指す。

完全同期はSCMの要件ではない。共有する能力と、独立に失敗できる能力の双方を保持する。

## 3. 二種類の連続性

### 3.1 共時的連続性

同じ時刻に複数の個体が存在し、同じ系の記録・記憶・共有状態・目的へ接続する。

ここでは、分業、競合、不一致、共有状態、局所拒否、統制、相関故障が問題になる。

### 3.2 通時的連続性

時間の経過とともに、系へ接続する個体が入れ替わる。

```text
T1: 個体A
T2: 個体B
T3: 個体C
```

または、同時複数個体を持つ系では次のようになる。

```text
T1: 個体A・B・C
T2: 個体B・C・D
T3: 個体D・E
```

ここでは、任務継続、個体交代、経験帰属、未確定状態、権限、Handoffが問題になる。

SCM v0.1参照プロファイルは、通時的連続性を先に実装する。

## 4. 基本構造 — 3層＋2面

| 構造 | 主な役割 | 主な時間幅 |
|---|---|---:|
| 局所自律層 | 即時判断、実体制御、局所作業、拒否 | ミリ秒〜秒 |
| 共有状態層 | 現在状態の集約、共有、競合・不一致の保持 | 秒〜分 |
| 上位統制層 | 目的、分業、優先順位、再計画、個体切替 | 分〜日 |
| 連続性面 | 記録、記憶、想起、物語、任務来歴 | 全期間 |
| 保証面 | 安全、権限、検証、隔離、監査 | 全時間幅 |

```text
        人間・組織・外部目的
                 │
                 ▼
            上位統制層
   目的・任務・優先順位・個体切替
                 │
              任務提案
                 ▼
            共有状態層
  世界状態・作業状態・資源・不一致・信頼度
      ▲          ▲          ▲
      │          │          │
   個体A       個体B       個体C
   局所自律     局所自律     局所自律
   実体状態     実体状態     実体状態
   拒否権       拒否権       拒否権

────────────────────────────
連続性面：記録・記憶・想起・物語・任務来歴
保証面　：安全・認証・検証・隔離・監査
────────────────────────────
```

参照プロファイルが同時活動個体数を一つに限定しても、この責務分離は残る。上位統制は次の個体を選択し、個体は任務を受諾・拒否し、保証面は切替と有効化の境界を監視する。

## 5. 局所自律

各個体は少なくとも次を保持する。

- 自身の観測
- 自身の実体・実行環境の状態
- 現在の任務
- 自身の能力と制約
- 即時の安全判断
- 通信断・実行不能時の行動
- 上位提案を拒否する能力

上位統制から個体へ渡されるものは、原則として低レベルの動作命令ではなく任務提案である。

個体は、受諾、条件付き受諾、保留、拒否、人間または上位系への引き上げを行える。

局所拒否権のない構成はSCMの要件を満たさず、中央遠隔制御型の構成に近い。

拒否権は、個体の自己申告を無条件に真実とみなすことを意味しない。拒否は安全側へ倒す制御として即時有効にできる一方、拒否理由は記録され、必要に応じて別経路で検証される。

## 6. 共有状態

共有状態は「真実の世界」ではない。

複数の個体が提出した観測、申告、推定、作業状態、資源状態を統合した、運用上の共有信念状態である。

共有される単位は、確定事実よりも主張に近い。

```text
共有主張 =
  内容
  観測・申告主体
  観測・申告時刻
  根拠
  信頼度
  有効範囲
  有効期限
  反証・不一致
```

単一個体の申告と、独立した観測・検証は区別される。

不一致は即座に一方へ潰さず、未確定状態として後継個体へ継承できなければならない。

すべての内部状態を共有する必要はない。高頻度制御値、一時キャッシュ、外部共有の必要がない内部処理は局所に残せる。

共有すべきなのは、他個体の判断と継承に必要な根拠、前提、結果である。

## 7. 上位統制

上位統制層は、次を扱う。

- 全体目的と完了条件
- タスク分解
- 個体への役割・任務提案
- 資源と時間の配分
- 優先順位変更
- 競合解消
- 障害時の再計画
- 個体の選択・停止・切替
- Handoff開始
- 人間や外部組織との接続

SCMは中央集権を必須としない。統制機能は複数のシステムへ分担できる。

必要なのは、個体をまたいで任務と連続性を束ねられることである。

## 8. 連続性面 — 記録・記憶・想起・物語

### 8.1 記録

何が起きたか、誰が観測・申告・実行したか、どの任務に属するか、何を根拠にしたかを追記型で保持する。

訂正が必要な場合も元記録を消さず、後続の記録または状態遷移として残す。

### 8.2 記憶

記録から、将来の判断へ持ち越す意味単位として保存されたもの。

記憶は根拠記録への参照を持つ。根拠を失った記憶は確定知識ではなく、仮説または由来不明として扱う。

### 8.3 想起

現在の個体、モデル、任務、権限、局所状態、リスクに応じて、必要な記録と記憶を現在の実行コンテキストへ持ち込む操作。

同じ記憶基盤へ接続していても、全個体が常に同じものを想起するわけではない。

### 8.4 物語

記録と記憶を時間的・因果的に接続した解釈。

複数の物語が併存してよい。ただし、物語は記録を解釈できるが、記録を書き換えてはならない。

## 9. 経験の所有

共有記憶を利用できることと、その経験主体であることは別である。

| 区分 | 意味 |
|---|---|
| 自己観測 | 現在の個体自身が観測した |
| 継承記録 | 他個体の記録へアクセスした |
| 系統記憶 | 複数記録から系として抽出された |
| 推論 | 記録をもとに推定した |
| 外部提供 | 人間や外部システムから与えられた |

個体Bが個体Aの観測記録を参照しただけで、「私は観測した」と表現してはならない。

## 10. 三種類のアイデンティティ

### 10.1 個体アイデンティティ

特定のモデル、プロセス、セッション、端末、身体などへ付与される。

個体Aの経験は、Bが参照できてもBの経験にはならない。

### 10.2 役割アイデンティティ

担当役割や任務上の位置へ付与され、個体間で移譲できる。

### 10.3 系アイデンティティ

記録、記憶、目的、権限、関係、任務来歴を継続して保持する上位単位。

接続個体集合や活動モデルが変わっても継続する。

系アイデンティティは、同一の意識を主張するものではなく、運用上の連続性を表す。

## 11. Handoff — 通時的連続性の中心操作

SCMの中心質問は次である。

> **個体Aが消え、個体Bが活動を継続するとき、何を系として保持し、何をBへ継承し、何を継承してはならないか。**

継承する対象には、少なくとも次が含まれる。

- 目的と任務
- 進捗と成果物
- 根拠記録と共有記憶
- 未確定事項と反証
- 現在有効な権限・制約
- 系の来歴

継承してはならないものには、少なくとも次が含まれる。

- 個体Aそのもののアイデンティティ
- Aの経験をB自身の経験とする一人称
- 根拠のない確定性
- 古い共有状態の無条件な有効性
- Aにだけ与えられた権限
- モデル内部の不可視な思考経路を同一の状態とみなすこと

Handoffは、出発個体が自身を複製する操作ではない。

> **系が記録と現在状態から、後継個体に必要な連続性を再構成する操作である。**

## 12. 保証面

保証面の原則は次である。

> **共有された知能は便利だが、正しいとは限らない。**

保証面は、権限確認、安全停止、異常個体の隔離、操作ログ、監査、人間介入、独立検証などを含みうる。

同時活動個体数が一つであっても、次の境界には保証が必要である。

- 次の個体へ渡す権限
- Handoffの鮮度
- 未確定状態の保持
- 経験帰属
- 任務受諾と拒否
- Narrativeと記録の権限分離

一般的な更新復元と相関故障の局所化は、最初の参照プロファイルでは適合を主張しない。

## 13. 設計不変条件

1. 個体の停止によって任務来歴が失われない。
2. 共有された情報には必ず出所がある。
3. 他個体の経験を自己経験として偽装しない。
4. 上位統制は局所安全判断を迂回できない。
5. 個体は不適切な任務を拒否できる。
6. 物語は記録を上書きできない。
7. 更新は段階展開され、巻き戻せる。
8. 一つの故障を個体・領域・系単位で隔離できる。

I7・I8は構造核に残すが、v0.1参照実装では適合を主張しない。I7の復元範囲とI8の一般的故障局所化は、将来版で規範文を精密化する。

## 14. SCMではないもの

- 局所自律と拒否権を持たない単なる中央制御
- 任務・記憶・来歴の継続を持たない単なるマルチエージェント
- 同じDBを読むだけの共有データベース
- 故障局所化を欠く完全同期クローン
- 意識や主観的自己の移送を主張する人格アップロード

## 15. プロジェクトの第一目的

SCMの第一目的は、共有連続性を持つ記憶系を構造的に設計・実装することである。

診断仕様、違反行列、ケースは、実装と並行して整備し、観測結果を構造へ還流させるための補助成果物である。

> **構造なき診断を先行させない。診断なき構造を固定しない。**

## 16. 現行参照プロファイルとの関係

SCM v0.1参照プロファイルは、次のように概念全体を限定する。

- 生成AIモデルまたはモデルへ結び付いた実行個体を扱う。
- 同時に活動する個体数を一つに限定する。
- モデル切替を個体交代として扱う。
- 記録・記憶・想起・物語・任務来歴の継続を中心に置く。
- 複数個体の同時稼働は将来プロファイルへ延期する。
- Physical AIは概念の射程に残すが、機体情報は将来プロファイルへ延期する。

この限定は、SCM Coreへ単一個体やソフトウェアだけを前提とする構造を埋め込むものではない。
