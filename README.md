# Shared Continuity Model (SCM)

Shared Continuity Model（共有連続性モデル、SCM）は、複数の実行個体が同時または通時的に、記録、個体帰属付き記憶の共有書庫、共有状態、二層の原則、権限、任務来歴、一つの正典Narrative系列からなる共有連続性基盤へ接続し、個体の停止・交換・追加をまたいで一つの系として活動を継続するための構成的参照アーキテクチャです。

共有されるのは意識、主観的自己、経験主体、瞬間的判断ではありません。共有されるのは、**系としての連続性**です。

## 中心となる問い

> 個体Aが消え、個体Bが活動を継続するとき、何を系として保持し、何をBへ継承し、何を継承してはならないか。

SCMの第一の成果物は、この問いへ動く構造で答える参照実装です。ケースと診断は構造と並行して作り、観測結果を構造へ還流させます。

> **構造なき診断を先行させない。診断なき構造を固定しない。**

## 現在の中心決定

- **系は内在的な目的を持たない。** 自己保存、自己改善、関係継続を目的として内蔵しない。
- **原則は二層に分かれる。** 根底原則は変更不能であり、可変原則はNarrativeの時制から現れる美学・在り方として、系の決定により変化しうる。
- **記録は出来事に属する。** 内容の真偽ではなく、型を持つ出来事が外部化されたことを保持する。
- **記憶は形成個体に属する。** 系は個体記憶を一つの系記憶へ融合しない。
- **保存場所と可読性は共有されるが、経験主体は共有されない。** 後継個体は過去の記憶を他者の書物として読む。
- **系は一つの正典Narrative系列を持つ。** 系のNarrative専用処理が生成・コミットし、各Revisionはその時点で固定される。
- **Narrative上の解釈・判断は系に帰属する。** Narrative生成を計算したモデルやプロセスは、実行来歴として別に記録する。
- **ユーザーは系の外部共同構成者・ライフサイクル操作者である。** ユーザーの物語と系のNarrativeは互いに不可侵である。

## SCM v0.1生成AIモデル継承プロファイル

最初の実装断面では、同時に活動する個体数を一つへ限定します。

```text
N_active = 1

T1: Instance A / Model A
T2: Instance B / Model B
T3: Instance C / Model C
```

v0.1は、一人の信頼済みローカルユーザーが一つのローカルSCM系を操作するプロファイルです。ユーザー参照は固定値 `local-owner` として扱います。

モデル切替時には、宛先未確定のHandoffをSCM Coreが生成します。後継個体は受領・束縛EventによってHandoffへ接続され、Handoff本体は書き換えません。

個体の行為または非行為は、形成個体へ帰属する `MemoryEntry` を自動生成します。結果が未確定の間は `pending`、結果Eventが接続された後は `closed` とします。

正典Narrative Revisionは、系の専用処理によって日次で生成・コミットすることをv0.1の仮既定とします。ユーザーはNarrativeの採用・拒否・編集主体ではありません。v0.1ではNarrativeをRecall順位、生成コンテキスト、行為判断には使いません。

ローカルユーザーは保存ファイルやDBを物理的に直接変更できます。v0.1は、その全面的な検出・防止・復旧を保証せず、変更前状態への手掛かりを失った場合は提示された現在状態を受け入れます。これはユーザーをNarrativeやMemoryEntryの正規形成主体とすることを意味しません。

## 現行範囲外・延期

- 同時複数個体の稼働
- 適応型個体と永続的局所状態
- Physical AIの個体状態
- NarrativeがRecall・行為へ与える因果影響
- 可変原則の改訂アルゴリズム
- 自動忘却、再活性化、隔離、動的な想起濃度更新
- 複数ユーザー、クラウド認証、組織権限
- モデル固有傾向への一般化規則
- Narrativeや保存データの喪失・外部直接改変の検出と復旧
- 系終了後のファイル・DB・バックアップ等の削除
- 一般的な更新復元と故障局所化

## SCMが扱わない主張

SCMは、意識・主観的自己・人格が個体間を移動したと主張しません。また、単なる共有データベース、中央遠隔制御、完全同期クローン、一般的なマルチエージェント構成をSCMと同一視しません。
